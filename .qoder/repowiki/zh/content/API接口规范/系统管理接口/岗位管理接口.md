## 简介
本文档详细说明岗位管理相关接口功能，涵盖岗位的增删改查、状态管理、与用户及部门的关联关系。同时描述岗位编码的唯一性约束、命名规范，以及在用户信息编辑和组织架构展示中的具体应用场景。

## 岗位增删改查接口

提供标准的RESTful接口用于岗位信息的全生命周期管理：

- **查询岗位列表**：`GET /system/post/list`
- **查询岗位详情**：`GET /system/post/{postId}`
- **新增岗位**：`POST /system/post`
- **修改岗位**：`PUT /system/post`
- **删除岗位**：`DELETE /system/post/{postId}`

前端通过`listPost`、`getPost`、`addPost`、`updatePost`、`delPost`等API方法调用实现对应功能。

## 岗位状态管理

系统支持对岗位进行启用/停用状态管理。虽然岗位本身未直接暴露状态字段，但通过用户状态联动机制实现岗位的实际可用性控制。当岗位下所有用户均被停用时，该岗位在组织架构中将不可见或不可选。

## 岗位与用户关联关系

岗位与用户之间存在多对多关联关系。一个用户可被分配至多个岗位，一个岗位也可包含多名用户。在用户管理模块中，可通过岗位选择器为用户分配岗位。

在用户编辑界面，通过`getUser`接口获取用户详情时，会同时返回其所属岗位信息（`postIds`字段），并在表单中渲染岗位选择控件。

## 岗位编码唯一性与命名规范

岗位编码（`postCode`）具有全局唯一性约束，确保系统内无重复岗位标识。命名规范要求岗位名称应简洁明确，反映实际职责，长度限制为2-20个字符，仅允许中文、英文、数字及基本符号，禁止使用特殊字符。

前端在新增或修改岗位时会对名称进行校验，确保符合规范。

## 用户信息编辑界面岗位选择器数据加载

在用户信息编辑界面，岗位选择器的数据通过以下方式加载：

1. 进入新增或编辑用户页面时，调用`getUser()`接口。
2. 该接口返回当前用户信息的同时，附带可选的岗位列表（`posts`字段）。
3. 前端将`posts`映射为选择器选项，供用户勾选。

岗位选择器为多选下拉框，支持选择多个岗位。

## 岗位与部门归属关系

岗位归属于特定部门，形成“部门 → 岗位 → 用户”的层级结构。每个岗位必须绑定一个部门，不能独立存在。部门与岗位为一对多关系。

在用户个人资料页面中，显示“所属部门”信息时，会同时展示部门名称和岗位组信息，格式为：`部门名称 / 岗位组`。

## 组织架构展示中的使用场景

在组织架构树中，岗位作为部门节点的子级展示。用户可在组织架构图中直观查看各部门下的岗位分布及人员构成。点击岗位节点可展开查看该岗位下所有在职员工列表。

岗位状态影响其在组织架构中的可见性：若岗位被逻辑删除或所有成员均停用，则该节点将置灰或隐藏。

## 岗位列表查询接口分页与响应字段

### 分页参数
岗位列表查询支持标准分页：
- `pageNum`：当前页码（默认1）
- `pageSize`：每页数量（默认10）
- 其他筛选条件：`postName`（岗位名称）、`status`（状态）

### 响应字段
| 字段 | 类型 | 说明 |
|------|------|------|
| `postId` | Long | 岗位ID |
| `postCode` | String | 岗位编码（唯一） |
| `postName` | String | 岗位名称 |
| `orderNum` | Integer | 显示顺序 |
| `status` | String | 状态（0正常 1停用） |
| `createBy` | String | 创建者 |
| `createTime` | DateTime | 创建时间 |
| `updateBy` | String | 更新者 |
| `updateTime` | DateTime | 更新时间 |
| `remark` | String | 备注 |

## 岗位人数统计计算逻辑

岗位人数统计通过以下方式实现：

1. 后端在查询岗位列表时，关联统计每个岗位下的有效用户数量。
2. 统计条件：用户状态为“正常”（`status=0`），且未被逻辑删除。
3. 结果通过扩展字段返回，如`userCount`。
4. 前端在岗位列表中展示该数值，用于快速了解各岗位人员规模。

此统计为实时计算，确保数据准确性。

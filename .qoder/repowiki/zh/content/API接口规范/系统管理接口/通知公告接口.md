## 简介
本接口文档旨在说明通知公告模块的完整功能设计，涵盖公告的发布、编辑、删除、状态切换（草稿/发布）、分页查询及前端展示等核心流程。系统通过统一的API接口实现公告全生命周期管理，支持多类型、多范围的公告发布机制。

## 核心功能
- 公告的增删改查操作
- 公告状态管理（草稿、发布）
- 分页查询与条件检索
- 按标题关键字和时间范围筛选
- 前端滚动展示数据获取
- 已读/未读状态标记

## API接口说明

### 公告列表查询
**功能**：分页获取公告列表，支持按标题关键字、发布时间范围、公告类型等条件检索  
**请求方式**：GET  
**接口地址**：`/system/notice/list`  
**请求参数**：
- `pageNum`：当前页码
- `pageSize`：每页数量
- `title`：公告标题（模糊匹配）
- `noticeType`：公告类型（通知、公告、警示）
- `status`：状态（0：草稿，1：发布）
- `createBy`：发布人
- `createTime`：创建时间范围（开始时间,结束时间）

**响应字段**：
- `noticeId`：公告ID
- `title`：公告标题
- `content`：公告内容
- `noticeType`：公告类型
- `status`：状态
- `createBy`：发布人
- `createTime`：创建时间
- `updateTime`：更新时间

### 查询公告详情
**功能**：根据公告ID获取详细信息  
**请求方式**：GET  
**接口地址**：`/system/notice/{noticeId}`  
**路径参数**：`noticeId`（公告唯一标识）

### 新增公告
**功能**：创建新的公告，可保存为草稿或直接发布  
**请求方式**：POST  
**接口地址**：`/system/notice`  
**请求体**：
- `title`：标题（必填）
- `content`：内容（必填）
- `noticeType`：类型（通知、公告、警示）
- `status`：状态（0：草稿，1：发布）
- `rangeType`：发布范围（全员/指定部门）
- `deptIds`：指定部门ID列表（当`rangeType=指定部门`时必填）

### 修改公告
**功能**：更新已有公告信息  
**请求方式**：PUT  
**接口地址**：`/system/notice`  
**请求体**：同新增公告，需包含`noticeId`

### 删除公告
**功能**：根据公告ID删除公告  
**请求方式**：DELETE  
**接口地址**：`/system/notice/{noticeId}`  
**路径参数**：`noticeId`

## 前端首页公告展示逻辑
首页通过轮询或定时请求获取最新发布的公告数据，用于滚动展示。前端调用公告列表接口，设置查询条件如下：
- `status=1`（仅获取已发布）
- `orderBy=create_time DESC`（按发布时间倒序）
- `pageSize=5~10`（限制展示数量）

前端实现自动轮播效果，每条公告停留3-5秒后切换至下一条。点击公告可跳转至详情页查看完整内容。

## 已读未读状态管理
系统通过用户行为记录实现公告已读/未读状态管理：
1. 用户进入公告详情页时，前端调用“标记为已读”接口
2. 后端记录`userId`与`noticeId`的关联关系
3. 首页展示时，前端同时请求“未读公告数量”接口
4. 未读公告在列表中以加粗或红点标识

> 注：当前代码库中未发现明确的已读状态接口，建议后续扩展`/system/notice/read`接口用于标记已读状态。

## 业务规则说明

### 公告字段规则
| 字段 | 规则说明 |
|------|----------|
| **标题** | 不超过100字符，不能为空 |
| **内容** | 支持富文本格式，不能为空 |
| **类型** | 枚举值：通知、公告、警示 |
| **状态** | 草稿（0）、发布（1） |
| **发布范围** | 全员 或 指定部门 |
| **指定部门** | 多选部门，仅当发布范围为“指定部门”时生效 |

### 权限控制
- 发布权限：仅限管理员或指定公告管理员角色
- 编辑权限：仅限公告创建者或管理员
- 删除权限：仅限管理员
- 查看权限：根据发布范围控制可见性

### 数据过滤规则
- 普通用户只能查看`status=1`且属于自己部门或全员发布的公告
- 管理员可查看所有公告（含草稿）
- 按时间范围查询时，支持`>=开始时间 AND <=结束时间`的区间匹配

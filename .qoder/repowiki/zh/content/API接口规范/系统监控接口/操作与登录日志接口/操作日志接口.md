## 简介
操作日志接口用于记录系统中用户的关键操作行为，支持安全审计、行为追溯和故障排查。该接口提供分页查询、条件筛选、单条删除、批量操作及清空日志等功能，是系统安全与运维的重要组成部分。

## 核心接口说明
操作日志功能由前后端协同实现，主要涉及以下核心接口：

- **GET /monitor/operlog/list**：分页查询操作日志列表，支持多种过滤条件
- **DELETE /monitor/operlog/{operId}**：删除指定ID的操作日志
- **DELETE /monitor/operlog/clean**：清空全部操作日志

这些接口通过API封装供前端调用，实现完整的日志管理能力。

## 查询操作日志列表
### 请求方式
使用 `GET` 方法请求 `/monitor/operlog/list` 接口。

### 分页参数
通过以下参数实现分页控制：
- `pageNum`：当前页码（从1开始）
- `pageSize`：每页记录数（通常为10、20、50、100）

### 过滤条件
支持多种条件组合查询：
- **时间范围**：通过 `startTime` 和 `endTime` 指定操作时间区间
- **操作类型**：根据 `logType` 字段过滤不同类型的操作（如借出、归还、违规等）
- **用户账号**：通过操作人字段 `operator` 进行精确或模糊匹配
- **业务状态**：根据 `status` 字段筛选特定状态的记录（如取刀、还刀、暂存等）

### 响应数据结构
返回的每条日志包含以下关键字段：

| 字段名 | 含义说明 |
|--------|----------|
| `lendUserName` | 取出人姓名 |
| `storageUserName` | 暂存人姓名 |
| `brandName` | 刀具品牌名称 |
| `cutterCode` | 刀具型号 |
| `specification` | 规格参数 |
| `quantity` | 操作数量 |
| `oldPrice` / `newPrice` | 老单价/新单价 |
| `oldStockNum` / `newStockNum` | 操作前后库存数 |
| `stockLoc` | 库位号 |
| `logType` | 日志类型（操作、借出、归还、暂存、违规） |
| `status` | 业务状态（取刀、还刀、收刀、暂存、完成、违规还刀） |
| `cabinetCode` | 刀柜编码 |
| `createTime` | 创建时间 |
| `operator` | 操作人 |
| `detailsCode` | 操作详情编码 |
| `remake` | 备注信息 |

## 删除与清空操作日志
### 删除单条日志
- **接口路径**：`DELETE /monitor/operlog/{operId}`
- **参数说明**：`operId` 为待删除日志的唯一标识
- **使用方法**：调用 `delOperlog(operId)` 方法，传入具体日志ID即可删除该条记录

### 清空全部日志
- **接口路径**：`DELETE /monitor/operlog/clean`
- **使用方法**：调用 `cleanOperlog()` 方法可清空所有操作日志
- **注意事项**：此操作不可逆，执行前需进行二次确认提示

## 前端审计页面实现
前端通过 `index.vue` 组件实现了完整的操作日志审计功能，主要包括：

### 分页展示
使用 `el-pagination` 组件实现分页控制，支持动态调整每页显示条数（10、20、50、100），并实时更新当前页码和总记录数。

### 条件筛选
提供丰富的查询条件：
- 时间选择器：支持选择开始时间和结束时间
- 下拉选择框：可按记录状态、排序类型、排序方式进行筛选
- 查询与重置按钮：实现条件提交和表单清空

### 批量删除与一键清空
- **批量删除**：通过表格的多选功能选择多条记录，调用删除接口批量处理
- **一键清空**：提供“清空”按钮，触发清空接口前进行确认对话框提示

## 实际应用场景
### 系统安全审计
通过操作日志全面记录用户对刀具的取用、归还、暂存等关键操作，确保所有行为可追溯，满足安全管理要求。

### 用户行为追溯
当发生异常操作（如违规还刀）时，可通过日志快速定位责任人、操作时间、涉及设备等信息，便于追责和改进流程。

### 故障排查
在系统出现数据不一致或库存异常时，可通过操作日志的时间线分析，找出问题发生的准确时间和操作序列，辅助快速定位原因。

### 统计分析
结合日志中的数量、金额、品牌等信息，可生成各类统计报表，为管理决策提供数据支持。

## 后端存储与性能优化
### 存储策略
- 操作日志采用结构化数据库存储，保证数据完整性和查询效率
- 关键字段建立索引（如操作时间、操作人、操作类型），提升查询性能
- 支持按时间分区存储，便于日志归档和清理

### 性能优化考虑
- 分页查询避免全表扫描，仅加载必要数据
- 提供批量删除接口，减少网络往返次数
- 支持异步导出功能，避免大文件导出阻塞主线程
- 清理过期日志接口可定期执行，防止日志表无限增长影响性能
